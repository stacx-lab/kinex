# What reference/ holds

- kinex-core.md: what a sub-agent can do in its environment. It is a Kinex session in a robot workspace: the device tools, `exec` for Python with `kinex.helpers`, and the host's shell and file tools.
- python-kinex/: the Python package a sub-agent's code imports as `kinex`, the same source the sub-agent runs. `__init__.py` documents what an `exec` script or a tool can call, `communication.py` the object that publishes, subscribes and requests, and `helpers/helpers.txt` lists the helper functions with the file each is implemented in. Code written for a sub-agent can be run offline against a stub of this package.
- builtin-tool/: Kinex's own tools, each a complete example of a tool directory.
- workspace/: the robot workspace every sub-agent starts in, as its `.kinex/` folder holds it: `workspace.yaml` and `devices/<device>/`, whose `profile.yaml` names the device's operations with their types and units. A function can name these operations itself; they are the same in every trial.

In a sub-agent's workspace, code in `.kinex/lib/` is importable from `exec` and from tools.

A library is installed into the sub-agent's workspace as it is, so it uses Kinex's own formats:

- A skill is `skills/<name>/SKILL.md`: a frontmatter block (`---`, then `name: <name>` and `description: <one line>`, then `---`) followed by the text. Both keys are required.
- A tool is `tools/<name>/` holding `tool.yaml` and its entry, `tool.py` unless `entry:` names another file. `tool.yaml` has `name` (lowercase snake_case, unique), `description`, `parameters` (a JSON Schema for the arguments object), and optionally `async: true` (the entry exports `async def main(args, io)` and reaches devices through `io`), `timeout_s` (default 120) and `devices` (device types that must be loaded). No other keys are accepted.
- `brief.md` is plain text.

improve_check loads the candidate the way Kinex would and reports what does not load. It does not run anything.
