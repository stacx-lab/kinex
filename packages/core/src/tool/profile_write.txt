Persist profile facts in the workspace:
- robot: partial manifest; identity requires id, name, platform and kind initially.
- device: partial profile; name is required, type on first write. Use setup-device and the selected guide for new devices.
- needed: {item,note?}; queue the reason without changing existing provenance.

Patches deep-merge. To switch a strict variant, supply the complete top-level section and list it in replace (e.g. ["intrinsics"]). Arrays replace wholesale. null removes an optional section only when listed in replace. Changing device type replaces its profile. Invalid updates are not saved.

Outstanding requests persist across reads and replacements. Clear a resolved request with needs_calibration:null in its section; the store rejects clearing incomplete facts. Unknown required facts remain ???. Set source to the origin of the data; keep diagnostics in calibration evidence.

New devices use loaded:false; activation uses the device tool (action="load") or /load, not profile edits. Profiles live at .kinex/devices/<name>/profile.yaml beside the driver, using the nearest .kinex/ in the current directory or its ancestors (the current directory's .kinex/ if none exists). Validation errors identify fields and the guide to consult.
