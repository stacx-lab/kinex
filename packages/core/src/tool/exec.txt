Run Python in the workspace's Kinex Python: python source, a kinex.lib program by name, or the main function of a file. Device environments and the world clock never choose this interpreter. Python cannot load/unload devices or control recording; lifecycle remains host-controlled. One execution approval covers composed operations.
python is the body of an async function: await directly and return the result. io, lib, runtime, args, pose and seconds are preset. For example:
  state = await io.read("arm.joint_state")
  image, depth = await lib.images.camera_frame("camera")
  return {"positions": state.position, "image": image}
Compute with NumPy arrays, poses and seconds on the world clock; lib functions return these and take them in any equivalent form. A pose is a scipy RigidTransform (a * b composes, .inv() inverts, .apply(points) moves points, .translation and .rotation read it), written [x, y, z, qx, qy, qz, qw]; pose(value) makes one from those seven numbers or a ROS Pose or Transform message. seconds(value) is the time of a stamp or stamped message. A message's array field, a list from your arguments or seven numbers pass to lib functions as they are.
The result is JSON-ready data: ROS messages, poses, NumPy values, dataclasses and tuples are converted, a pose to its seven numbers and a time to seconds. A returned sensor_msgs/Image, or a pathlib.Path of an image file, is attached for you to see, in order; include camera names and stamps. Report failure by raising. Printing does not return or attach anything; do not print catalogs or raw streams unless requested.
Discover devices on demand, without starting them: runtime.devices() lists devices and readiness, runtime.operations(name) the declared operations, even if unloaded, and runtime.describe("device.operation") the ROS payload schema. Use actual operation names from these queries, not names inferred from device types. Load required devices through the host first.
io reaches devices: await io.read(operation) takes the next message of an output topic; io.subscribe(operation, depth=1) with await stream.next(timeout_s=...) follows one; await io.publish(operation, message) commands a topic with a ROS message or field mapping; await io.request(operation, **fields) calls a service. In a mapping, give seconds for a Time or Duration field, a pose for a Pose or Transform field and arrays for numeric fields; your mapping is left unchanged. Sending is not measured arrival. World wait operations own scheduling, one wait at a time. Observations and tf2 queries never advance world time. Bound work, inspect fresh measured feedback, and stop on terminal task status. Service rejections raise kinex.OperationError with operation, response and structured details; inspect the response and relevant feedback before deciding how to recover.
lib is the program library: every public function of a kinex.lib module is a program. Find modules and signatures with the lib tool, call them as lib.module.function(...) and compose them with ordinary Python, asyncio.gather included. program runs one by name with args as its keyword arguments, such as program "frames.lookup_transform".
subagent asks a model for a judgment inside a program, so a saved program can decide what it sees without returning to you: reply = await subagent("Is the mug centred in both views? Answer yes or no.", show={"front": image, "wrist": other}). from kinex import subagent in a module. It sees only the instruction and the named items in show (camera image messages and image Paths as images, other values as text), has no tools, and answers in text. Say exactly what form the reply must take, parse and check it in the program, and return the images to yourself when the reply is unusable. Call it where the robot is at rest. Its replies appear in the invocation's output.
Save reusable code as a module in the workspace's .kinex/lib, at any depth: a docstring saying what the module contains, then functions with typed signatures and docstrings, async when they use io. They take no io parameter; import io from kinex and other modules from kinex.lib. A complete closed-loop task belongs there too, so it runs again by name without rewriting it.
Failure, timeout or cancellation stops every device this invocation commanded; success leaves their motion running.
