Resolve the workspace robot's calibration queue. Run calib_plan first. Scope work
to $ARGUMENTS when supplied; otherwise work the loaded devices' queue in dependency
order. Skip unloaded devices. If no workspace exists, point to /onboarding; if
nothing is queued, report that result.

Match each item by exact id or its section:type selector, such as
intrinsics:wrist_cam [intrinsics:rgb]. Load the matching skill. If several match,
choose using the recorded reason and available equipment; ask only when a user
preference or missing fact determines the procedure. If none matches, report the
gap or write an embodiment-specific skill under the project's .kinex/skill/.
Access items use setup-device and the selected device guide.

Before physical preparation, verify the required loaded devices answer. Prefer
existing measured/factory data and device-owned URDF models over manual procedures.
Reach estimates describe a joint device in its base frame; never persist sampled
reachability as measured world geometry. World geometry remains optional.

Follow the skill's collection procedure and quality gate. Scripts run from the
skill's directory using core Python and the library paths supplied in context.
Scratch files and raw solver results belong in .kinex/calib/<skill-name>/; device facts belong in
profiles. Install missing dependencies in the prepared runtime within the user's
authorization. Ask for physical setup, contact reports and missing measurements,
without duplicating tool permission prompts.

Use the skill's motion speed. move_to scales planning rates with speedFraction. calib_sample reads measured state; settling
requires measured velocities and fresh timestamps. Without that feedback, collect
an ordinary sample after the procedure's independent stationary confirmation.

After a quality gate passes, write the measured section with source:calibration,
method and calibrated_at when known. Include needs_calibration:null only when the
whole item is resolved; the store checks completeness before clearing it. Planning
never clears requests. Partial results keep their marker and must not be reported
as complete. On failure preserve existing calibration and update the marker's reason.

calib_write normally deep-merges partial patches. When changing a strict variant,
read the profile, supply the complete changed section, and name it in replace
(e.g. replace:["intrinsics"]). Omitted sections remain intact. A replaced section
keeps its outstanding request unless explicitly cleared. null removes an optional
section only when that section is listed in replace.

Re-run calib_plan after writes. Finish with resolved items, remaining reasons and
readiness. Do not infer calibration quality from populated fields alone.
