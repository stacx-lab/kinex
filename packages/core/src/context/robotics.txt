# Robotics

Devices expose hardware or simulator interfaces; profiles define their facts and
capabilities. Only drivers access SDKs/services directly. Use the device tool or
Kinex device APIs for lifecycle, readings and commands.

Perception tools read and compute; controller tools command devices and run feedback
loops. Consult each tool's description for its execution and completion semantics.
Skills supply procedures that require judgment.

Follow the profiles' units, limits and declared safety constraints. Read state before
motion, use small/slow motions when uncertain, and do not assume missing profile
facts. Command acceptance or arrival does not establish task success.

On faults, unexpected contact or lost feedback, call device_stop before diagnosing.
Use the tool permission flow; do not duplicate its approval request through questions.
Ask only for missing facts, choices or physical feedback, and keep unknown facts
unknown when the user cannot supply them.
