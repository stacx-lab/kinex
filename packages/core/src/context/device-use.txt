<device_conventions>
Read profiles for parameters and injected type conventions for operations. Units and vector order follow the profile. ??? means unresolved; null follows its field and never means numeric zero.
Custom per-device DEVICE.md files are allowed only for certain types.
Use /register and setup-device to provision an unloaded device or repair its driver. Write facts through profile_write; preserve provenance and unknowns. Queue missing measurements with kind=needed and clear resolved requests explicitly with needs_calibration:null. New profiles remain unloaded; edits preserve activation intent. /unregister confirms removal of a device and its files.
Load inactive devices through the device tool or /load. status never starts services; unload releases resources. Python tools cannot change lifecycle. Reload persistent drivers after editing code or cached configuration.
Profile completeness describes available facts, not calibration quality or safe motion. Use the facts required by the selected operation; unrelated unknowns and calibration requests do not block tasks. Operation validation and permissions still apply.
Frames use device for its base and device:frame for a local frame. Local frames declare {parent_frame, translation_m, rotation_xyzw}; null parent means device base, null transform components mean unknown. Mount maps child coordinates into its parent: p_parent = R * p_child + translation_m. Use metres, right-handed frames and unit xyzw quaternions. Disconnected roots have no implied transform; use relative_pose to resolve relationships.
Observations use numeric timestamp in seconds: acquisition time, or receipt time when unavailable. Cached readings retain it; compare timestamps only within the same clock.
Actuator writes submit a buffer with duration_s and return {execution_id, state}: an opaque submission ID and measured state, not completion. New writes replace pending references; stop clears affected buffers. Use world.wait to pace execution.
Special devices like legged bases use mode as their single state/mode selector. control.device_modes declares the available modes and transitions. control.write and the custom Use guide declare supported fields, units and frames. Omit motion fields for state-only transitions; verify measured state readiness before motion.
kinex.devices runs calls concurrently and preserves result order, without guaranteeing simultaneous sampling or atomic effects. Never retry uncertain writes.
</device_conventions>
